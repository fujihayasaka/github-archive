# FilterPicker

A library of components to build your own pickers with a search `Filter` component nested.
Start from any (or both) of the 2 base dialog components:

- `SelectPickerDialog`: a foundation to build a single-select or multi-select dialog, so it returns a list of selected items.
- `DynamicPickerDialog`: a foundation to build a picker dialog based on a filter query, so it returns a string with the query.

Then implement pickers based on the base picker components:

- `SingleSelectPicker`: a foundation to build a single-select picker, selecting only one item.
- `MultiSelectPicker`: a foundation to build a single-select picker, selecting multiple items.
- `DynamicPicker`: a foundation to build a dynamic picker, selecting a query that targets multiple items.

Reference implementation: `repos-picker`.

## How to use

There's a common configuration for both modes (select & dynamic) defined by `ItemConfig`.
It defines:

- the copy literals needed
- the endpoint used to search
- the rendering instructions specific to the item type

You can create any of these component pickers for your `Fruit` item type:

- Implement your single-select picker
  1. Create a new component `SingleSelectFruitPickerDialog` rendering a `SelectPickerDialog` with `selectionVariant="single"`.
  2. Then a new component `SingleSelectFruitPicker` rendering a nested `SingleSelectPicker` and the previous `SingleSelectFruitPickerDialog`.
- Implement your multi-select picker
  1. Create a new component `MultiSelectFruitPickerDialog` rendering a `SelectPickerDialog` with `selectionVariant="multiple"`.
  2. Then a new component `MultiSelectFruitPicker` rendering a nested `MultiSelectPicker` and the previous `MultiSelectFruitPickerDialog`.
- Implement your dynamic picker
  1. Create a new component `DynamicFruitPickerDialog` rendering a `DynamicPickerDialog`.
  2. Then a new component `DynamicFruitPicker` rendering a nested `DynamicPicker` and the previous `DynamicFruitPickerDialog`.

What is not included:

- Backend implementation of search experience: each implementer needs to provide it. We recommend a route like `<entity>/picker/search`.
- Storage of selection on the backend (either the selected entities, their IDs, or the query returned by the dynamic picker).
